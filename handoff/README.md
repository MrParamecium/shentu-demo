# 交接书架（handoff）

我们俩（程浩翔 @MrParamecium、黄友涵 @JohanHuang2005）的任务布置、进度和交接都在这个文件夹里完成。
**每次开始开发前先读这里，结束时把进度写回这里。**

## 文件夹里有什么

| 文件 | 作用 | 谁来改 |
|---|---|---|
| [`BOARD.md`](BOARD.md) | **任务看板**：所有任务一览、谁负责、什么状态 | 布置任务的人新增；做任务的人改状态 |
| [`tasks/`](tasks/) | 每个任务一个文件：要做什么、怎么算完成、进度日志 | 做任务的人持续更新 |
| [`sessions/`](sessions/) | 每次开发结束写一条交接记录：做了什么、卡在哪、下一步 | 每次开发结束的人 |
| [`DECISIONS.md`](DECISIONS.md) | 已经定下来的决定（技术栈、产品方向），避免反复讨论 | 两人商量后再改 |
| [`CONTEXT.md`](CONTEXT.md) | 项目背景速览：线上地址、目录结构、本地怎么跑 | 有变化时更新 |
| [`templates/`](templates/) | 新建任务、写交接记录用的模板 | 一般不改 |

## 开发流程（每次都这样）

**开始前**
1. `git pull`，读 `BOARD.md`，找到分给你的任务
2. 打开对应的 `tasks/T-xxx.md`，读「要做什么」「完成标准」和最新的进度日志
3. 读 `sessions/` 里最新的一两条交接记录
4. 把任务状态改成 `🔄 进行中`

**开发中**
- 一个任务一个分支，分支名用任务编号：`t-003-program-library`
- 有新发现、遇到坑、改了方案，随时写进任务文件的「进度日志」

**结束时**
1. 更新任务文件的进度日志和勾选清单
2. 在 `sessions/` 新建一条交接记录（复制 `templates/session.md`），文件名 `日期-名字.md`，如 `2026-10-24-youhan.md`
3. 更新 `BOARD.md` 里的状态
4. 提交 PR，PR 描述里写上任务编号，如「T-003」

## 布置新任务（主要是浩翔）
1. 复制 `templates/task.md` 到 `tasks/T-编号-简短英文名.md`，编号接着 `BOARD.md` 里最大的往下排
2. 写清楚「背景」「要做什么」「完成标准」「参考资料」
3. 在 `BOARD.md` 加一行，填负责人

## 状态图标
`⬜ 待开始` `🔄 进行中` `👀 待审核`（PR 已开） `✅ 完成` `⏸ 暂缓` `🚫 阻塞`（写清楚卡在哪）

## 规矩
- **密钥、密码、API key 一律不写进这里**，也不写进代码。只写「去哪里拿」
- 不确定的事写「待确认」，不要写成已经定了
- 用中文写，短句，能让对方不问你就看懂
